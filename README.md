# agheri.it

This repository contains the German and Italian static website for
`www.agheri.it`. The pages are written in a small, deliberately simple subset
of Markdown and generated by `build.py`.

## Project structure

```text
.
├── build.py                    Site generator
├── src/
│   ├── assets/                 CSS and images copied to the website
│   ├── content/                Source pages used by the generator
│   │   ├── de/                 German pages
│   │   ├── it/                 Italian pages
│   │   ├── index.md            Landing page
│   │   └── keywords.md         SEO keyword groups
│   ├── layouts/base.html       Shared HTML layout
├── dist/                       Generated website; not committed
└── .github/workflows/deploy.yml
                                Build and FTP deployment workflow
```

Only files below `src/content/` are discovered as pages.
`src/content/index.md` is the source for `/`.

## Editing a page

Every page starts with a metadata block between two `---` lines. The content
below that block is Markdown.

```markdown
---
title: "Example page"
description: "Description shown to search engines."
keywords: de
lang: de
path: /de/example/
nav: home
image: /assets/images/example.jpg
image_alt: "Description of the image"
---

# Page heading

Page content goes here.
```

### Page metadata

| Field | Purpose |
| --- | --- |
| `title` | Browser title and search-result title. |
| `description` | Search-engine description. |
| `keywords` | Keyword group from `src/content/keywords.md`; normally `root`, `de`, or `it`. If omitted, the page language is used. |
| `lang` | Page language, currently `de`, `it`, or `en`. The default is `en`. |
| `path` | Required output URL. `/de/contact/` becomes `dist/de/contact/index.html`. A Markdown file without `path` is not built. |
| `nav` | Navigation item to highlight: `home`, `services`, `specialties`, `contact`, or `links`. It also selects the matching destination for the language switch. |
| `image` | Optional site-relative image URL, for example `/assets/images/work1.jpg`. |
| `image_alt` | Alternative text for the page image. Use a short description for accessibility. |
| `body_class` | Optional CSS class placed on `<body>`. The default is `page`. |
| `build` | Set to `false` for supporting Markdown files that must not become pages. |

Metadata values are plain text. Quotes around a value are optional and are
removed by the generator.

## Supported Markdown

The site uses a small custom renderer rather than a full Markdown package.
These forms are supported:

```markdown
# Heading level 1
## Heading level 2
### Heading level 3

A paragraph of text.
A second line in the same paragraph.

- First bullet
- Second bullet

This is **bold text** and this is `inline code`.

[Internal link](/de/)
[External link](https://example.com){new_tab}
```

- Headings from `#` through `######` are supported.
- Empty lines separate paragraphs and lists.
- Consecutive non-empty lines in a paragraph are separated with `<br>`.
- Lines beginning with `- ` become an unordered list.
- `**text**` creates bold text.
- Backticks create inline code.
- `[label](url)` creates a normal link in the current browser tab.
- Add `{new_tab}` directly after a link to open it in a new tab. The generated
  link also includes `rel="noopener noreferrer"` for safety.

`{new_tab}` is a site-specific extension. The source is still valid Markdown:
other Markdown readers simply treat the marker as ordinary text, while
`build.py` recognizes and removes it when generating the link.

Raw HTML and unsupported Markdown constructs are displayed as text. Keep the
content syntax simple and check the generated page when introducing a new
format.

## Links

Use a normal link for another page on this website:

```markdown
[Kontakt](/de/kontakt/)
```

Use the friendly marker for a website that should open separately:

```markdown
[Visit Genua](https://www.visitgenoa.it/de){new_tab}
```

Email links use the normal Markdown form:

```markdown
[agheri.tech@gmail.com](mailto:agheri.tech@gmail.com)
```

## Images and other assets

Source assets belong under `src/assets/`. During every build, that complete
directory is copied to `dist/assets/`.

For example:

```text
src/assets/images/weblinks1.jpg
```

is available on the generated site as:

```text
/assets/images/weblinks1.jpg
```

Always edit or add the source file under `src/assets/`; never edit `dist/`
directly. Use consistent lowercase filenames and avoid case-only renames such
as `Weblinks1.jpg` to `weblinks1.jpg`. The production server uses Windows/IIS,
where those names refer to the same physical file, and the FTP synchronizer
can otherwise lose track of the file.

## Navigation and language switching

The navigation labels and URLs are defined in `NAV` inside `build.py`.
Equivalent German and Italian page URLs are defined in `LANG_SWITCH`.

When adding a page that should appear in the main navigation:

1. Add the page to `src/content/de/` and/or `src/content/it/`.
2. Add its navigation entry to the appropriate `NAV` list.
3. Add both language destinations to `LANG_SWITCH`.
4. Use the same `nav` value in the page metadata.

Pages such as the imprint and disclaimer do not need to appear in `NAV`, but
their language-switch mappings are still present in `LANG_SWITCH`.

## Keywords

SEO keyword groups live in `src/content/keywords.md`. The file has
`build: false` because it supplies metadata rather than a web page.

Each second-level heading names a group, and its bullets are combined into the
page's keywords meta tag:

```markdown
## de

- Übersetzungen
- Italienisch
- Deutsch
```

A page selects the group with `keywords: de`, `keywords: it`, or
`keywords: root` in its metadata.

## Building locally

The generator uses only the Python standard library and has no package
dependencies.

```bash
python3 build.py
```

Each build:

1. Deletes the existing `dist/` directory.
2. Copies `src/assets/` to `dist/assets/`.
3. Reads every Markdown file below `src/content/`.
4. Generates an `index.html` at each page's configured `path`.

Because `dist/` is generated and listed in `.gitignore`, it should not be
committed.

## Deployment

Pushing to `main` or `master` starts the GitHub Actions workflow in
`.github/workflows/deploy.yml`. It checks out the repository, runs the build,
and uploads `dist/` to `/httpdocs/` over FTP.

The repository must provide these GitHub Actions secrets:

- `FTP_USERNAME`
- `FTP_PASSWORD`

The FTP deployment action stores `.ftp-deploy-sync-state.json` in the server
directory. It uses that file to decide which generated files changed. If the
state says a file exists but the file is missing from the server, delete only
that state file through the hosting control panel and rerun the workflow. The
next deployment will perform a complete resynchronization.

## Common checks

- A page is missing: confirm that it is under `src/content/`, has a `path`, and
  does not have `build: false`.
- An image is missing: confirm that it is under `src/assets/images/` and that
  the URL, spelling, and capitalization match.
- A source edit has no effect: confirm that the edit was made under `src/`,
  not in generated `dist/`.
- A deployment succeeds but a file is absent: check the FTP synchronization
  state and avoid case-only filename changes.
- A language switch goes to the wrong page: check `LANG_SWITCH` and the
  page's `nav` metadata.
